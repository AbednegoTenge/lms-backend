# API Contract — School Management System

## Conventions

* Base URL: `/api/v1/`
* Auth: `Authorization: Bearer <access_token>` on all protected routes
* Response envelope:

  ```json
  { "success": true, "data": {}, "message": "Action completed." }{ "success": false, "data": null, "message": "Error description.", "errors": {} }
  ```
* Pagination (all list endpoints):

  ```json
  {  "success": true,  "data": {    "count": 120,    "next": "/api/v1/students/?page=3",    "previous": "/api/v1/students/?page=1",    "results": []  }}
  ```

  Default page size: 20. Max: 100. Query param: `?page=2&page_size=50`.
* Timestamps: ISO 8601 UTC (`2024-09-01T08:00:00Z`)
* All IDs: UUID strings

## Auth

### `POST /api/v1/auth/login/`

**Public** · Throttle: `5/min`

Login uses `school_id` (not email) + the password set by the admin.

```json
Request:  { "school_id": "STD001", "password": "AdminSetPassword123" }
Response (normal login): {
  "data": {
    "access": "<jwt>",
    "refresh": "<jwt>",
    "force_password_reset": false,
    "user": { "id": "uuid", "school_id": "STD001", "full_name": "", "roles": ["STUDENT"] }
  }
}
Response (first login — password reset required): {
  "data": {
    "access": "<jwt>",
    "refresh": "<jwt>",
    "force_password_reset": true,
    "user": { "id": "uuid", "school_id": "STD001", "full_name": "", "roles": ["STUDENT"] }
  }
}
```

When `force_password_reset: true`, the frontend **must** redirect the user to the
password reset page before allowing any other action. The issued access token is
restricted — it can only call `POST /api/v1/auth/first-login-reset/`. All other
endpoints return HTTP 403 with `"message": "Password reset required before continuing."`.

This is enforced by a custom permission class `RequiresPasswordChange` that checks
`request.user.must_change_password`.

### `POST /api/v1/auth/first-login-reset/`

**Auth required** (restricted token, `must_change_password=True` users only) · Throttle: `5/min`

```json
Request: {
  "new_password": "MyNewSecurePass1!",
  "confirm_password": "MyNewSecurePass1!"
}
Response: {
  "success": true,
  "data": {
    "access": "<new_full_jwt>",
    "refresh": "<new_refresh_jwt>"
  },
  "message": "Password updated. You are now logged in."
}
```

On success:

* Sets `must_change_password = False`
* Blacklists the restricted token
* Issues fresh, unrestricted JWT pair
* Logs `FIRST_LOGIN_RESET` to `AuditLog`

Password validation rules (enforced server-side):

* Minimum 8 characters
* At least one uppercase letter
* At least one digit
* Cannot match the admin-set temporary password

### `POST /api/v1/auth/refresh/`

**Public** · Throttle: `10/min`

```json
Request:  { "refresh": "<token>" }
Response: { "data": { "access": "<token>" } }
```

### `POST /api/v1/auth/logout/`

**Auth required** · Blacklists refresh token.

```json
Request:  { "refresh": "<token>" }
Response: { "success": true, "message": "Logged out." }
```

### `POST /api/v1/auth/change-password/`

**Auth required** · Only for users where `must_change_password = False` (normal logged-in users)

```json
Request:  { "old_password": "", "new_password": "", "confirm_password": "" }
Response: { "success": true, "message": "Password updated." }
```

## Users

### `GET /api/v1/users/`

**Admin, IT Support** · Filterable: `?role=TEACHER&is_active=true&search=STD`

```json
Response.data.results: [
  {
    "id": "uuid",
    "school_id": "TCH003",
    "full_name": "Ama Asante",
    "roles": ["TEACHER"],
    "is_active": true,
    "must_change_password": false
  }
]
```

Uses `select_related('userrole_set__role')`. Paginated.

### `POST /api/v1/users/`

**Admin (creates Teacher/Student/Principal), Super Admin (any role)**

```json
Request: {
  "first_name": "Ama",
  "last_name": "Asante",
  "phone": "+233244000000",
  "email": "ama.asante@school.gh",
  "password": "TempPass123!",
  "roles": ["TEACHER"]
}
Response.data: {
  "id": "uuid",
  "school_id": "TCH004",
  "full_name": "Ama Asante",
  "roles": ["TEACHER"],
  "must_change_password": true,
  "message": "User created. They must reset their password on first login."
}
```

`school_id` is auto-generated by the server based on the role. Admin provides the
initial password — it is stored hashed. `must_change_password` is always `true`
on creation. Email is optional but recommended for future password recovery.

### `GET /api/v1/users/{id}/`

**Admin, Principal, IT Support, or self**

### `PATCH /api/v1/users/{id}/`

**Admin or self (own profile only)**

```json
Request: { "first_name": "", "phone": "", "profile_photo": "<file>" }
```

### `DELETE /api/v1/users/{id}/` (soft-delete)

**Admin, Super Admin** · Sets `is_active=False`.

### `POST /api/v1/users/{id}/assign-role/`

**Super Admin only** (for IT_SUPPORT role); **Admin** for other roles

```json
Request:  { "role": "TEACHER" }
Response: { "success": true, "message": "Role assigned." }
```

Invalidates `user:{id}:roles` cache.

## Academic Year & Terms

### `GET/POST /api/v1/academic-years/`

**Admin** (write) · **All roles** (read)

### `GET/PATCH /api/v1/academic-years/{id}/`

**Admin** (write)

### `GET/POST /api/v1/terms/`

**Admin** (write) · **All roles** (read)

### `POST /api/v1/terms/transition/`

**Admin only** · Throttle: `2/hour`

```json
Request:  { "term_id": "uuid" }
Response: {
  "success": true,
  "data": {
    "promoted": 45,
    "graduated": 12,
    "new_term": "Term 1 2025/2026"
  }
}
```

Business logic:

* If `term_number < 3`: increment all active students' current term.
* If `term_number == 3` and `level < 3`: reset term to 1, increment level.
* If `term_number == 3` and `level == 3`: set `status=GRADUATED`.
* Mark all `StudentFee` with `status != FULLY_PAID` for old term as `OVERDUE`.
* Generate new `StudentFee` records for new term (Celery task).
  All wrapped in a DB transaction.

## Error Codes

| HTTP | Meaning                                                            |
| ---- | ------------------------------------------------------------------ |
| 400  | Validation error —`errors`field has field-level detail          |
| 401  | Missing or expired JWT                                             |
| 403  | Authenticated but role not permitted                               |
| 404  | Object not found                                                   |
| 409  | Conflict (duplicate enrollment, already submitted, etc.)           |
| 422  | Business rule violation (e.g. attempt limit exceeded, quiz closed) |
| 429  | Rate limit exceeded                                                |
| 500  | Internal server error — do not expose stack trace in production   |
